---
change: 155-retire-exclusive-gate
kind: behavior
---
The shared-cluster gate now retires an exclusive lease's cluster. When an `Exclusive` lease is released, the cluster is marked retired before it is terminated, and the gate refuses a retained `*ceph.Container`, and every handle taken from it (OSD, monitor and manager handles, pools, clients, fault and override operations), with `ceph.ErrSharedCluster`, except for the operations that only read state. A termination that fails leaves a running cluster that stays retired until `SharedCluster.Close` ends it, where it used to keep admitting the retained handles. A `ceph.ClientConfig` that a tenant got from `Tenant.Client` or `Tenant.CreateClient` stays a tenant handle: the gate refuses it in every mode, including during an exclusive lease that takes the same cluster, because admission follows the handle's provenance and not the cluster's current mode. No public name changes. The embedded `Container.Container` field of the lent `*ceph.Container` is a plain testcontainers container and is not behind the gate, a known constraint of testcontainers compatibility.
